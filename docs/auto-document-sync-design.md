# 固定目录自动同步设计

## 目标

用户只需把求职资料放入项目根目录 `data/documents/`，系统就能自动建立或更新知识库，无需执行导入命令。资料目录与索引数据继续由 Git 忽略，不上传 GitHub。

## 目录约定

```text
data/documents/
├─ md/    Markdown 文档
├─ txt/   纯文本
└─ pdf/   可提取文字的 PDF
```

三个子目录用于帮助整理，不作为严格校验条件。扫描器递归检查 `data/documents/`，并以实际扩展名识别 `.md`、`.txt` 和 `.pdf`；文件放错子目录时仍可索引。目录在后端启动时自动创建。

Docker 模式把宿主机 `./data/documents` 只读挂载为容器内 `/knowledge`。网页与后端只能读取资料，不能永久删除本地原文件。

## 扫描策略

- 后端启动时执行一次扫描。
- 后端每 60 秒扫描一次。
- 网页保留“立即扫描”按钮，用于主动触发同一套扫描流程，不是上传按钮。
- 同一时间只允许一个扫描任务；重复触发返回“扫描正在进行”。
- 先比较文件路径、大小和修改时间；没有变化时不计算向量、不调用 Ollama。
- 新文件或变化文件需保持大小和修改时间稳定至少 10 秒再处理，避免读取尚未复制完成的 PDF。
- 单文件默认上限 25 MB，超限文件显示为未处理。
- 扫描任务每次只处理支持的格式，其他文件直接忽略。

## 索引策略

- 新文件：解析、分块、生成 Embedding 并写入 Qdrant 和 SQLite。
- 未变化文件：跳过，不重复调用 Ollama。
- 内容变化：新索引成功后才删除旧向量，避免更新失败导致原知识失效。
- Embedding 每批最多 32 个分块，批次之间允许交互式提问先执行，降低显存与延迟峰值。
- 同一路径、同一内容且上次失败的文件不会每 60 秒重复尝试；文件修改或用户点击“重试”后才再次处理。
- 扫描和索引在后台线程执行，不阻塞 FastAPI 的网页请求。

## 删除流程

固定目录是资料来源，知识库不自动永久删除内容。

1. 用户从 `data/documents/` 删除或移走原文件。
2. 下一次扫描把对应文档标记为“源文件已移除”，保留现有向量。
3. 文档管理页显示“确认清除”操作。
4. 用户确认后，系统删除对应 Qdrant 向量，并在 SQLite 中软删除记录。

如果用户误移文件，在确认清除前把相同文件放回原路径，下一次扫描会恢复为“已索引”，无需重新生成向量。若文件内容发生变化，则按更新流程重新索引。

删除按钮不会删除宿主机文件。仍在固定目录中的文件不提供“确认清除”，避免清除后又被下一轮扫描自动导入。

## 页面设计

文档管理页顶部改为自动同步状态卡：

- 显示监控目录：`data/documents/`。
- 显示支持格式与三个推荐子目录。
- 显示最近扫描时间和结果摘要。
- 提供“立即扫描”按钮。
- 扫描进行中禁用按钮，并显示明确状态。

文档表格新增“源文件已移除”状态。只有该状态显示“确认清除”；失败文件显示错误原因和“重试”，超限或不支持的文件在扫描摘要中提示。

## 接口

- `POST /api/v1/documents/scan`：立即触发扫描，返回本次扫描摘要。
- `GET /api/v1/documents/scan`：返回监控目录、扫描间隔、是否扫描中、最近扫描摘要。
- `GET /api/v1/documents`：继续返回文档列表，增加 `missing` 状态。
- `DELETE /api/v1/documents/{document_id}`：清除向量并软删除记录；固定目录来源仅允许清除 `missing` 状态。
- `POST /api/v1/documents/{document_id}/retry`：允许失败文件在内容未变化时手动重试。

接口只返回相对显示路径，不暴露宿主机绝对路径。

## 异常处理

- Qdrant 或 Ollama 不可用：记录单个文件失败，不终止整个扫描。
- 复制中的文件：进入等待状态，下一轮扫描再处理。
- 超过上限：不读取正文、不调用 Ollama，在摘要中计数。
- 扫描重叠：后触发的任务不重复执行。
- 文件在扫描过程中被移走：记录本次失败，下一轮修正为缺失。
- 后端重启：重新扫描一次；已索引且内容不变的文件只计算一次哈希，不生成新向量。

## 验证

后端测试覆盖：

- 自动创建三个分类目录。
- 新文件、未变化文件、修改文件的同步。
- 文件需稳定 10 秒。
- Embedding 以最多 32 个分块分批。
- 失败文件不自动重复尝试。
- 删除文件后标记缺失，放回后恢复。
- 缺失文件确认清除后删除向量。
- 并发扫描只运行一个。
- API 不返回本地绝对路径。

前端测试覆盖：

- 自动同步状态卡和“立即扫描”按钮。
- 扫描中与失败提示。
- “源文件已移除”状态和二次确认清除。
- 空知识库时提示用户把资料放入三个子目录。

最后运行后端测试、Ruff、前端测试、类型检查和构建，并在 Docker Compose 下验证目录挂载、启动扫描和网页接口。
